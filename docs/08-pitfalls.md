# 08 已知陷阱

遇到奇怪的音频问题先查这里。

## 响度与峰值

1. **比较响度要同响度**。处理后更响会让人觉得"更好听",这是错觉。A/B 必须按 docs/02 第 3 节匹配响度。
2. **采样峰值 ≠ 真峰值**。采样峰值 −1 dBFS 的音频,转成 MP3 或经 DAC 重建后可能超过 0 dBFS。护栏用的是真峰值(4 倍过采样)。
3. **MP3/AAC 编码会抬高峰值**。有损导出必须:渲染时 ceiling 设 −1.5 dBTP → 编码 → 解码再测;若解码后 > −1.0 dBTP,把 ceiling 再降 0.5 dB 重新渲染(最多 2 次),仍失败则 `GUARDRAIL_FAILED`。
4. **短时间音频的 LUFS 不可靠**。BS.1770 需要至少 0.4 s 的块;30 秒预览段的响度只用于 A/B 匹配,不用于判断"整首是否达标"。
5. **LUFS 里没有静音门限以外的东西**。大段静音不会拉低综合响度(有门限),但会让真峰值/LRA 的解读变怪。`silence_gaps` fixture 就是为了测这个。

## 数据与格式

6. **形状**。pedalboard 期望 `(channels, samples)` 的 float32;soundfile/librosa 常给 `(samples, channels)`。进入 `audio/` 之前统一转换,`AudioBuffer` 数据类里显式携带采样率。
7. **整数转浮点**。16-bit PCM 除以 32768;24-bit 除以 8388608。不要用 `/32767`。
8. **16-bit 导出需要抖动(dither)**。从 float 降到 16-bit 时加 TPDF dither,否则低电平会有量化失真。24-bit 与 FLAC 24-bit 不需要。
9. **采样率**。内部保持源采样率,不要无故重采样。若必须重采样(导出选项指定),用 `scipy.signal.resample_poly` 或 ffmpeg 的 `soxr`,并在重采样后重新检查护栏。
10. **声道**。单声道源:`stereo_width` 旁路,不要把单声道复制成"假立体声"再加宽。

## DSP

11. **限制器有延迟(lookahead)**。pedalboard 的 Limiter 输出可能比输入延后若干采样;渲染后要对齐,保证 G4(时长/对齐)。测试里用脉冲验证对齐。
12. **压缩器不要加 makeup**。响度由 `loudness` 阶段统一决定,否则两处增益会打架。
13. **饱和会产生高次谐波并混叠**。`saturation` 要 4 倍过采样后再降采样。
14. **Mid/Side 宽度**。`width` 大于 1 会放大侧声道,可能让单声道折叠后掉能量(G6)。先算折叠损失再决定。
15. **EQ 增益叠加**。多个频段重叠时增益会相加。自适应规则追加的切/提要计入 G7 的上限。
16. **不要"凭空加高频"**。源文件带宽只有 16 kHz 时,高架 EQ 提升的只是噪声底。见自适应规则"带宽受限"。

## 工程

17. **子进程安全**。ffmpeg 一律 `subprocess.run([...], shell=False, timeout=...)`;输入输出路径由服务端生成;`-i` 前不拼接任何用户字符串。
18. **上传校验用 ffprobe**,不用扩展名或 `Content-Type`。校验顺序:大小(流式检查,边收边断)→ ffprobe → 时长/声道 → 完整解码。
19. **临时文件清理**。任务失败也要清理半成品;`finally` 里处理,不要依赖 TTL。
20. **缓存键必须包含 recipe 的规范化 JSON 哈希**(键排序、浮点统一格式)。否则"同一份 recipe 不命中缓存"或"不同 recipe 命中同一缓存"。
21. **浏览器自动播放**。`AudioContext` 必须在用户手势之后 `resume()`。
22. **浏览器解码**。`decodeAudioData` 对 WAV 最稳;预览用 16-bit PCM WAV 就是这个原因。
23. **Range 请求**。`<audio>` 或 fetch 流式读取需要 `Accept-Ranges`;没有它,拖动进度会失败。
24. **时区/文件名**。导出文件名里不要加时间戳(会让用户重复下载时一堆文件),除非后续有需求。

## 流程

25. **不要用被测代码生成期望值**。测试里的期望值用解析公式、独立实现(ffmpeg)或固定常数,否则测试永远通过。
26. **改了预设就要重跑 `make eval`**。预设的小改动可能让某个 fixture 破坏护栏。
27. **你听不到**。看到"听起来不错"之类的结论只能来自人。

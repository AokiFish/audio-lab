# 01 产品定义

## 目标用户与场景

用 Suno / Udio 等工具生成歌曲的创作者。他们拿到成品后觉得"差一点",但不懂音频工程。
他们想要的是:选一个想要的声音 → 听到变化 → 下载。

## 产品原则

1. 默认简单:新用户不需要学任何音频知识。
2. 按目的组织:用"温暖""通透"这样的目标,不用"EQ""压缩"。
3. 专业能力不缩水:同一份 recipe,专业用户可以在"处理详情"里看到并编辑每个节点。
4. 结果可见:所有处理都能同响度对比、能撤销、能重来。
5. 不堆砌功能:没有被指标或人工试听验证过的效果,不进入界面。
6. 一套界面、一套设计语言。不做"简易版"和"专业版"两个站。

## MVP 范围

用户流程:上传 → 自动分析 → 选择声音目标 → A/B 试听(可调强度) → 导出。

### 声音目标(MVP 只做 4 个)

| id | 中文名 | 一句话 | 说明 |
|---|---|---|---|
| `balanced` | 均衡清晰 | 干净、平衡,默认选项 | 温和修整,最安全 |
| `warm` | 温暖醇厚 | 更柔和、更有厚度 | 低频略增,高频略收 |
| `bright` | 明亮通透 | 更清楚、更有空气感 | 中高频与高频略增 |
| `punch` | 紧实有力 | 低频更紧,整体更有冲击 | 低频控制 + 动态处理 |

每个目标有一个强度滑块(0–100%,默认 70%)。

### 导出

WAV(24-bit)、FLAC、MP3(320 kbps)。响度目标三档:流媒体 -14 LUFS(默认)、-16 LUFS、保持原响度。

## 明确不做(MVP)

- 分轨/人声分离,因此没有"只处理人声""只处理乐器"。4 个目标都是对整首混音做处理
- 降噪、修复削波、音色转换等 AI 模型
- 登录、支付、项目管理、历史版本、批处理
- 桌面软件
- "2000 种音效"。预设数量不是目标,效果可验证才是
- 参考曲匹配、多段压缩、动态 EQ、参数自动化(放在 M6 之后)

## 产品必须诚实的地方

- 不声称能修复生成式音频本身的缺陷(失真、人声伪影、错误音符)
- 如果检测到音源本身是低码率有损文件(高频被截断),不凭空"加高频",而是在界面提示并关闭对应增益
- 如果检测到音源已经削波,提示"无法修复已有削波"

## 成功标准

- 新用户在 60 秒内、不看说明,完成一次"上传到导出"
- 所有导出文件满足 docs/02 的安全护栏
- A/B 试听同响度,用户听到的是音色差异而不是音量差异
- 人工试听:在测试曲目上,4 个目标的最终效果由负责人确认"不比原曲差,且方向符合名称"
